# Dash Builder notes

`redesign/dash-builder.html`: pick a car and years, see every gauge system that fits in real
photos. The 1969 Camaro (pilot) first gets a 3D walk-around that climbs into the driver's seat.

## How pages are built

- Static HTML in `redesign/` (Vercel's output directory, no build command on deploy).
- `tools/build_pages.py` generates most pages with one shared shell: `page()` writes the head,
  `header()`, `footer()` and the menu script. It also rewrites the header and footer of the
  hand-built pages (`index.html`, `camaro-1969-rtx.html`, `dealers.html`) and the footer of the
  catalog pages in `shop/`, and rebuilds `sitemap.html` and `search-index.json`.
- `tools/build_catalog.py` writes the 1,000+ pages in `shop/` from a crawl cache of the live site.
  It uses the same `page()` shell from `build_pages.py`. It needs the cache, so it is not run for
  this change.
- `dash-builder.html` is generated by `dash_builder()` in `build_pages.py`. Run
  `python tools/build_pages.py` after changing it.
- Styles: `redesign/styles.css` (tokens at the top). Fonts: Barlow and Barlow Condensed.

## Data sources

| What | Where | Used by |
| --- | --- | --- |
| Fitment: which series (G, R, H, V, D) fit each car and year range | `PLATFORMS` in `redesign/garage.js` (`window.DDGarage.PLATFORMS`) | Dash Finder, My Garage, `fit.js`, Dash Builder |
| Series names and taglines | `SERIES` in `redesign/garage.js` (moved from `dash-finder.js`, so both use one copy) | Dash Finder, Dash Builder |
| Year range helper (`'1968-77'` to a list of years) | `yearsOf` in `redesign/garage.js` (moved from `fit.js`) | `fit.js`, Dash Builder |
| Product fit (store categories and model years each product page is for) | `data-cats` / `data-years` on `#fit` in each `shop/*-p*.html`, written by `build_catalog.py` | `fit.js`, Dash Builder (through the JSON below) |
| SKU, title, price, versions | `<script type="application/json" data-b="items">` in each product page | `shop.js`, Dash Builder (through the JSON below) |
| Lighting theme photos | `Theme:` photos in the product gallery, turned into `.theme-chip` buttons (`data-src`, name) by `theme_switcher()` in `build_catalog.py` | `shop.js`, Dash Builder (through the JSON below) |
| Main product photo | First `img/shop/prd-<product id>-*.webp` on the product page | Dash Builder (through the JSON below) |

`redesign/dash-builder-data.json` is written by `builder_data()` in `build_pages.py` from the built
product pages. It holds only what the builder needs for each GRFX, RTX, HDX, VHX and VFD3 product
that has car fit data: id, title, URL, series, main SKU, price, main photo, store categories,
model years, a console-gauges flag (title says "console") and its theme photos. It is not a second
copy of fitment: which series fit which car and years still comes only from `garage.js`. The
builder lists a series when `garage.js` says it fits and a product page exists for that car line
and those years (matched the same way `fit.js` matches: category plus overlapping years).

Coverage check (October 2026): 152 of the 153 car/years/series pairs in `garage.js` have a product
page. The one gap is HDX for the 1970-81 Camaro, which the builder leaves out rather than listing a
series it can't show or link to.

The same JSON lists optional files that exist, so the page never requests a missing file:
`dash` (per-car dash photos in `redesign/img/dash/<car>-<years>.webp`, e.g. `camaro-1969.webp`)
and `models` (3D models in `redesign/models/`). Add a file, then run `python tools/build_pages.py`.

## URL parameters

`dash-builder.html?car=camaro&years=1969&system=RTX&theme=Emerald&console=1`

- `car`: platform id from `garage.js` (`camaro`, `corvette`, `mustang`...).
- `years`: the year range label from `garage.js` (`1969`, `1968-77`).
- `system`: GRFX, RTX, HDX, VHX or VFD3.
- `theme`: a theme name from the product's photos (case doesn't matter).
- `console=1`: show the console-gauge versions.

Pre-fill order: URL, then the car saved in My Garage, then empty. Changes update the URL with
`history.replaceState`. Product pages take `?theme=<name>` and open on that theme photo (`shop.js`).

## 3D pilot (1969 Camaro)

- Three.js is pinned in `package.json` (devDependencies) and vendored by
  `node scripts/vendor-three.mjs` into `redesign/js/vendor/three/<version>/`: `three.module.min.js`,
  `GLTFLoader.min.js`, `DRACOLoader.min.js` and the Draco decoder (`draco/`). Three.js no longer
  ships a minified module build, so the script minifies with esbuild (also pinned). No CDN.
- The page's import map points `three` at the vendored file. `dash-builder-3d.js` is imported only
  when the picker holds a 1969 Camaro, WebGL works and reduced motion is off.
- Until `redesign/models/camaro-69.glb` exists, the page builds a stand-in car from simple shapes.

### Rules for camaro-69.glb (for the 3D artist)

- File: `redesign/models/camaro-69.glb`, Draco compressed, under 5 MB. After adding it, run
  `python tools/build_pages.py` so the page knows it exists.
- Units: meters (a 1969 Camaro is about 4.7 m long). Y up. The front of the car faces +Z (the
  glTF forward axis). The page centers the car on the ground for you.
- Paint: the body paint material must be named `Paint`. The page recolors it red.
- `DriverEye`: an empty object at the driver's eye point (left seat, about head height). The
  camera ends here.
- `Cluster`: an empty object at the center of the gauge cluster. The camera looks at it.
- The camera flies in through the back glass, so the back window must be glass (or open) with no
  solid parts behind it on the path to `DriverEye`. Faces should be single sided so the camera can
  see out from inside.
- If `DriverEye` or `Cluster` is missing, or the file fails to load, the page uses the stand-in car.

### Scroll stage

| Stage progress | What happens |
| --- | --- |
| 0 to 42% | Turntable: the car turns from a front 3/4 view to a rear view |
| 42 to 46% | Hold on the rear view |
| 46 to 80% | The camera moves through the back glass to `DriverEye`, turning to look at `Cluster` |
| 82 to 92% | The real product photo fades in over the scene (the dash view) |

Rendering stops when the stage is offscreen. "Skip to the dash" jumps straight to the dash view.

### Fallbacks

Any other car, no WebGL, or `prefers-reduced-motion: reduce`: no 3D stage. The dash view shows at
once with the line "3D view is coming for more cars."

### Where to get a model

Free models on sites like CGTrader often carry an editorial-only license, which doesn't allow use on
a store page, and many show a real car maker's badges. Buy or commission a model with a commercial
license, and have the artist follow the rules above.

## Tracking

`track(eventName, data)` in `dash-builder.js` does nothing yet. It is called on `builder_open`,
`car_selected`, `reached_dash`, `system_selected`, `theme_selected` and `click_see_system`.
Wire it to analytics later.
